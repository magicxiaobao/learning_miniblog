# 代码测试与质量保障

在软件开发中，[[测试驱动开发]]和[[质量保障]]是确保应用程序可靠性和健壮性的关键环节。本文将探讨Go语言中的测试方法和质量保障技术，以Miniblog项目为例。

## Go语言测试基础

Go语言内置了测试框架，主要通过 `testing` 包提供支持。标准的测试文件命名为 `xxx_test.go`，测试函数以 `Test` 开头。

### 单元测试基本结构

```go
package example

import "testing"

func TestAdd(t *testing.T) {
    // 准备测试数据
    a, b := 1, 2
    expected := 3
    
    // 执行被测试函数
    result := Add(a, b)
    
    // 验证结果
    if result != expected {
        t.Errorf("Add(%d, %d) = %d; expected %d", a, b, result, expected)
    }
}
```

### 表格驱动测试

表格驱动测试是Go中常用的测试模式，特别适合测试需要多个输入组合的函数：

```go
func TestAdd(t *testing.T) {
    // 定义测试用例
    tests := []struct {
        name     string
        a, b     int
        expected int
    }{
        {"正数相加", 1, 2, 3},
        {"负数相加", -1, -2, -3},
        {"正负相加", 1, -2, -1},
    }
    
    // 执行测试用例
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            result := Add(tt.a, tt.b)
            if result != tt.expected {
                t.Errorf("Add(%d, %d) = %d; expected %d", 
                    tt.a, tt.b, result, tt.expected)
            }
        })
    }
}
```

## 测试类型

### 单元测试

单元测试关注于代码的最小可测试单元，通常是函数或方法。目标是验证组件的行为是否符合预期。

在Miniblog项目中，我们为关键功能编写单元测试：

```go
// post包的单元测试示例
func TestPostController_Get(t *testing.T) {
    // 创建模拟存储和控制器
    mockDB := &mockgorm.DB{}
    mockAuthz := &mockauth.Authz{}
    ctrl := &post.Controller{
        DB:       mockDB,
        Authz:    mockAuthz,
        PostRepo: repository.NewPostRepository(mockDB),
    }
    
    // 模拟Gin上下文
    c, _ := gin.CreateTestContext(httptest.NewRecorder())
    c.AddParam("postID", "test-post-id")
    
    // 模拟数据库行为
    mockDB.On("Where").Return(mockDB)
    mockDB.On("First").Run(func(args mock.Arguments) {
        // 填充模拟数据到传递的结构体指针中
        post := args.Get(0).(*model.PostM)
        post.PostID = "test-post-id"
        post.Title = "Test Post"
        // ...其他字段
    }).Return(nil)
    
    // 执行测试
    ctrl.Get(c)
    
    // 验证响应
    // ...
}
```

### 集成测试

集成测试验证多个组件协同工作时的行为。在Miniblog中，我们测试控制器与数据库、缓存等外部依赖的交互：

```go
func TestUserLogin_Integration(t *testing.T) {
    // 跳过CI环境
    if os.Getenv("CI") != "" {
        t.Skip("Skipping integration test in CI environment")
    }
    
    // 初始化测试数据库
    db := initTestDB(t)
    defer cleanupTestDB(db)
    
    // 创建测试用户
    hashedPassword, _ := auth.Encrypt("testpassword")
    db.Create(&model.UserM{
        Username: "testuser",
        Password: hashedPassword,
        // ...其他字段
    })
    
    // 创建测试服务器
    router := gin.New()
    userCtrl := user.New(db, nil)
    router.POST("/login", userCtrl.Login)
    
    // 构造登录请求
    reqBody := `{"username":"testuser","password":"testpassword"}`
    req := httptest.NewRequest("POST", "/login", strings.NewReader(reqBody))
    req.Header.Set("Content-Type", "application/json")
    
    // 执行请求
    w := httptest.NewRecorder()
    router.ServeHTTP(w, req)
    
    // 验证响应
    assert.Equal(t, http.StatusOK, w.Code)
    // 验证响应体包含token
    var resp struct {
        Code    int
        Message string
        Data    struct {
            Token string
        }
    }
    json.Unmarshal(w.Body.Bytes(), &resp)
    assert.NotEmpty(t, resp.Data.Token)
}
```

### 性能测试

性能测试用于评估代码的效率，比如执行时间和内存使用情况。Go使用以 `Benchmark` 开头的函数进行性能测试：

```go
func BenchmarkPostRepo_List(b *testing.B) {
    // 初始化测试环境
    db := initTestDB(b)
    repo := repository.NewPostRepository(db)
    ctx := context.Background()
    
    // 重置计时器
    b.ResetTimer()
    
    // 运行 b.N 次测试
    for i := 0; i < b.N; i++ {
        posts, count, err := repo.List(ctx, 0, 10)
        if err != nil {
            b.Fatal(err)
        }
        if count < 0 || len(posts) > 10 {
            b.Fatalf("unexpected result: count=%d, posts=%d", count, len(posts))
        }
    }
}
```

## 模拟技术

### 接口模拟

Go的接口特性使模拟外部依赖变得简单。我们可以创建模拟实现来替代真实依赖：

```go
// 定义存储库接口
type PostRepository interface {
    Get(ctx context.Context, postID string) (*model.PostM, error)
    // ...其他方法
}

// 模拟实现
type MockPostRepository struct {
    mock.Mock
}

func (m *MockPostRepository) Get(ctx context.Context, postID string) (*model.PostM, error) {
    args := m.Called(ctx, postID)
    if args.Get(0) == nil {
        return nil, args.Error(1)
    }
    return args.Get(0).(*model.PostM), args.Error(1)
}
```

### 使用testify库

[testify](https://github.com/stretchr/testify)是Go中流行的测试辅助库，提供了断言、模拟和套件功能：

```go
import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/mock"
)

func TestUserController_Get(t *testing.T) {
    // 创建模拟对象
    mockRepo := new(MockUserRepository)
    
    // 设置预期行为
    mockRepo.On("Get", mock.Anything, "testuser").Return(&model.UserM{
        Username: "testuser",
        Email:    "test@example.com",
    }, nil)
    
    // 创建控制器并注入模拟
    ctrl := &UserController{
        UserRepo: mockRepo,
    }
    
    // 执行测试
    user, err := ctrl.GetUser(context.Background(), "testuser")
    
    // 断言结果
    assert.NoError(t, err)
    assert.Equal(t, "testuser", user.Username)
    assert.Equal(t, "test@example.com", user.Email)
    
    // 验证预期行为被调用
    mockRepo.AssertExpectations(t)
}
```

## HTTP测试

Go提供了`httptest`包用于HTTP处理程序测试：

```go
func TestLoginHandler(t *testing.T) {
    // 创建路由器
    router := gin.New()
    router.POST("/login", LoginHandler)
    
    // 创建测试请求
    reqBody := `{"username":"testuser","password":"password"}`
    req := httptest.NewRequest("POST", "/login", strings.NewReader(reqBody))
    req.Header.Set("Content-Type", "application/json")
    
    // 记录响应
    w := httptest.NewRecorder()
    
    // 服务请求
    router.ServeHTTP(w, req)
    
    // 检查状态码
    assert.Equal(t, http.StatusOK, w.Code)
    
    // 解析响应体
    var resp map[string]interface{}
    json.Unmarshal(w.Body.Bytes(), &resp)
    
    // 检查响应内容
    assert.Equal(t, float64(0), resp["code"])
    assert.Contains(t, resp, "data")
}
```

## 代码覆盖率

Go内置了代码覆盖率工具，可以测量测试覆盖了多少代码：

```bash
# 运行测试并生成覆盖率文件
go test -coverprofile=coverage.out ./...

# 查看覆盖率报告
go tool cover -html=coverage.out
```

在Miniblog项目中，我们设置了覆盖率目标（例如70%以上），以确保关键代码得到测试。

## 持续集成

持续集成(CI)可以自动运行测试、检查代码质量和构建应用。示例GitHub Actions配置：

```yaml
name: Go Tests

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    
    - name: Set up Go
      uses: actions/setup-go@v3
      with:
        go-version: 1.18
    
    - name: Install dependencies
      run: go mod download
    
    - name: Run tests
      run: go test -race -coverprofile=coverage.txt -covermode=atomic ./...
    
    - name: Upload coverage to Codecov
      uses: codecov/codecov-action@v3
      with:
        file: ./coverage.txt
```

## 实际案例：测试控制器

下面是Miniblog项目中的实际测试示例：

```go
// 测试获取帖子控制器
func TestPostController_Get(t *testing.T) {
    // 定义测试用例
    tests := []struct {
        name           string
        postID         string
        setupMocks     func(*mockgorm.DB, *mockauth.Authz)
        expectedStatus int
        expectedPost   *post.PostResponse
    }{
        {
            name:   "成功获取帖子",
            postID: "test-post-id",
            setupMocks: func(db *mockgorm.DB, authz *mockauth.Authz) {
                // 设置数据库mock
                db.On("Where", "postID = ?", "test-post-id").Return(db)
                db.On("First", mock.AnythingOfType("*model.PostM")).
                    Run(func(args mock.Arguments) {
                        p := args.Get(0).(*model.PostM)
                        p.PostID = "test-post-id"
                        p.Title = "测试文章"
                        p.Content = "测试内容"
                        p.Username = "testuser"
                        p.CreatedAt = time.Now()
                        p.UpdatedAt = time.Now()
                    }).Return(nil)
            },
            expectedStatus: http.StatusOK,
            expectedPost: &post.PostResponse{
                PostID:   "test-post-id",
                Title:    "测试文章",
                Content:  "测试内容",
                Username: "testuser",
            },
        },
        {
            name:   "帖子不存在",
            postID: "nonexistent-post",
            setupMocks: func(db *mockgorm.DB, authz *mockauth.Authz) {
                db.On("Where", "postID = ?", "nonexistent-post").Return(db)
                db.On("First", mock.AnythingOfType("*model.PostM")).
                    Return(gorm.ErrRecordNotFound)
            },
            expectedStatus: http.StatusNotFound,
            expectedPost:   nil,
        },
    }
    
    // 执行测试用例
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // 初始化模拟对象
            mockDB := new(mockgorm.DB)
            mockAuthz := new(mockauth.Authz)
            
            // 设置模拟行为
            if tt.setupMocks != nil {
                tt.setupMocks(mockDB, mockAuthz)
            }
            
            // 创建控制器
            ctrl := post.Controller{
                DB:    mockDB,
                Authz: mockAuthz,
                PostRepo: repository.NewPostRepository(mockDB),
            }
            
            // 创建测试上下文
            w := httptest.NewRecorder()
            c, _ := gin.CreateTestContext(w)
            c.AddParam("postID", tt.postID)
            
            // 执行被测函数
            ctrl.Get(c)
            
            // 验证响应状态码
            assert.Equal(t, tt.expectedStatus, w.Code)
            
            // 解析响应
            if tt.expectedPost != nil {
                var resp struct {
                    Code    int
                    Message string
                    Data    *post.PostResponse
                }
                err := json.Unmarshal(w.Body.Bytes(), &resp)
                assert.NoError(t, err)
                assert.Equal(t, 0, resp.Code)
                assert.Equal(t, tt.expectedPost.PostID, resp.Data.PostID)
                assert.Equal(t, tt.expectedPost.Title, resp.Data.Title)
                assert.Equal(t, tt.expectedPost.Content, resp.Data.Content)
                assert.Equal(t, tt.expectedPost.Username, resp.Data.Username)
            }
            
            // 验证模拟是否按预期调用
            mockDB.AssertExpectations(t)
            mockAuthz.AssertExpectations(t)
        })
    }
}
```

## 测试最佳实践

1. **测试关键路径**：优先测试应用的核心功能和复杂逻辑
2. **独立测试**：确保测试是独立的，不依赖于其他测试的状态
3. **可重复性**：测试应该是确定性的，多次运行得到相同结果
4. **快速测试**：测试应该快速执行，以便于频繁运行
5. **模拟外部依赖**：使用模拟对象替代数据库、API调用等外部依赖
6. **测试边界条件**：测试正常输入和边界情况
7. **使用表格驱动测试**：简化多个相似测试用例的编写
8. **检查测试覆盖率**：定期检查测试覆盖率，但不要只为提高覆盖率而测试
9. **集成到CI/CD流程**：确保每次代码提交都会运行测试
