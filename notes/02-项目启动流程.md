# 项目启动流程

[[miniblog]] 项目的启动流程是学习 Go 应用程序设计的重要组成部分。通过分析启动流程，我们可以了解一个完整的 Go Web 应用是如何从启动到提供服务的。

## 入口函数

项目启动的入口是 `cmd/miniblog/main.go`：

```go
func main() {
    command := miniblog.NewMiniBlogCommand()
    if err := command.Execute(); err != nil {
        os.Exit(2)
    }
}
```

这是标准的 Go 程序入口，它做了两件事：
1. 创建一个命令行应用对象 `command`
2. 执行这个命令，如果出错则以错误码 2 退出

## 命令行参数解析

miniblog 使用 [[cobra]] 库来处理命令行参数，在 `internal/miniblog/miniblog.go` 中：

```go
func NewMiniBlogCommand() *cobra.Command {
    cmd := &cobra.Command{
        Use: "miniblog",
        Short: "A good Go practical project",
        Long: `A good Go practical project, used to create user with basic information.
        
Find more miniblog information at:
    https://github.com/marmotedu/miniblog#readme`,

        SilenceUsage: true,
        RunE: func(cmd *cobra.Command, args []string) error {
            // 如果 `--version=true`，则打印版本并退出
            verflag.PrintAndExitIfRequested()

            // 初始化日志
            log.Init(logOptions())
            defer log.Sync() // Sync 将缓存中的日志刷新到磁盘文件中

            return run()
        },
        // ...
    }

    // 以下设置，使得 initConfig 函数在每个命令运行时都会被调用以读取配置
    cobra.OnInitialize(initConfig)

    // 添加命令行参数
    cmd.PersistentFlags().StringVarP(&cfgFile, "config", "c", "", "The path to the miniblog configuration file. Empty string for no configuration file.")
    cmd.Flags().BoolP("toggle", "t", false, "Help message for toggle")
    verflag.AddFlags(cmd.PersistentFlags())

    return cmd
}
```

这段代码完成了以下工作：
- 创建并配置 cobra 命令对象，设置名称、描述等基本信息
- 设置 `RunE` 函数，这是命令执行时会调用的主函数
- 注册 `initConfig` 函数到命令初始化回调中
- 添加命令行参数支持，如 `--config`、`--version` 等

## 配置加载

miniblog 使用 [[viper]] 库进行配置管理，在 `internal/miniblog/helper.go` 中：

```go
func initConfig() {
    if cfgFile != "" {
        // 从命令行选项指定的配置文件中读取
        viper.SetConfigFile(cfgFile)
    } else {
        // 查找用户主目录
        home, err := os.UserHomeDir()
        cobra.CheckErr(err)

        // 将用 `$HOME/<recommendedHomeDir>` 目录加入到配置文件的搜索路径中
        viper.AddConfigPath(filepath.Join(home, recommendedHomeDir))

        // 把当前目录加入到配置文件的搜索路径中
        viper.AddConfigPath(".")

        // 设置配置文件格式为 YAML
        viper.SetConfigType("yaml")

        // 配置文件名称
        viper.SetConfigName(defaultConfigName)
    }

    // 读取匹配的环境变量
    viper.AutomaticEnv()

    // 读取环境变量的前缀为 MINIBLOG
    viper.SetEnvPrefix("MINIBLOG")

    // 以下 2 行，将 viper.Get(key) key 字符串中 '.' 和 '-' 替换为 '_'
    replacer := strings.NewReplacer(".", "_")
    viper.SetEnvKeyReplacer(replacer)

    // 读取配置文件
    if err := viper.ReadInConfig(); err != nil {
        log.Errorw("Failed to read viper configuration file", "err", err)
    }

    log.Debugw("Using config file", "file", viper.ConfigFileUsed())
}
```

配置加载的流程是：
1. 如果指定了配置文件路径，直接使用该文件
2. 否则，在预定义位置查找默认配置文件（用户主目录下的 `.miniblog` 目录和当前目录）
3. 设置环境变量前缀，允许通过环境变量覆盖配置项
4. 最后读取并加载配置文件

## 核心启动流程

在 `internal/miniblog/miniblog.go` 的 `run()` 函数中包含了主要的启动逻辑：

```go
func run() error {
    // 初始化 store 层
    if err := initStore(); err != nil {
        return err
    }

    // 设置 token 包的签发密钥，用于 token 包 token 的签发和解析
    token.Init(viper.GetString("jwt-secret"), known.XUsernameKey)

    // 设置 Gin 模式
    gin.SetMode(viper.GetString("runmode"))

    // 创建 Gin 引擎
    g := gin.New()

    // gin.Recovery() 中间件，用来捕获任何 panic，并恢复
    mws := []gin.HandlerFunc{gin.Recovery(), mw.NoCache, mw.Cors, mw.Secure, mw.RequestID()}

    g.Use(mws...)

    if err := installRouters(g); err != nil {
        return err
    }

    // 创建并运行 HTTP 服务器
    httpsrv := startInsecureServer(g)

    // 创建并运行 HTTPS 服务器
    httpssrv := startSecureServer(g)

    // 创建并运行 GRPC 服务器
    grpcsrv := startGRPCServer()

    // 等待中断信号优雅地关闭服务器（10 秒超时)
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    <-quit
    log.Infow("Shutting down server ...")

    // 创建 ctx 用于通知服务器 goroutine, 它有 10 秒时间完成当前正在处理的请求
    ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()

    // 优雅关闭服务
    if err := httpsrv.Shutdown(ctx); err != nil {
        log.Errorw("Insecure Server forced to shutdown", "err", err)
        return err
    }
    if err := httpssrv.Shutdown(ctx); err != nil {
        log.Errorw("Secure Server forced to shutdown", "err", err)
        return err
    }

    grpcsrv.GracefulStop()

    log.Infow("Server exiting")

    return nil
}
```

启动过程包括以下步骤：
1. 初始化数据存储层 (store)
2. 初始化 JWT token 工具
3. 配置 Gin Web 框架
4. 注册全局中间件
5. 安装路由（通过 `installRouters` 函数）
6. 启动 HTTP、HTTPS 和 gRPC 服务器
7. 设置信号处理，实现优雅关闭

## 路由注册

路由注册在 `internal/miniblog/router.go` 中的 `installRouters` 函数中完成：

```go
func installRouters(g *gin.Engine) error {
    // 注册 404 Handler
    g.NoRoute(func(c *gin.Context) {
        core.WriteResponse(c, errno.ErrPageNotFound, nil)
    })

    // 注册 /healthz handler
    g.GET("/healthz", func(c *gin.Context) {
        log.C(c).Infow("Healthz function called")
        core.WriteResponse(c, nil, map[string]string{"status": "ok"})
    })

    // 注册 pprof 路由
    pprof.Register(g)

    // 初始化授权模块
    authz, err := auth.NewAuthz(store.S.DB())
    if err != nil {
        return err
    }

    // 创建控制器实例
    uc := user.New(store.S, authz)
    pc := post.New(store.S)

    g.POST("/login", uc.Login)

    // 创建 v1 路由分组
    v1 := g.Group("/v1")
    {
        // 用户相关路由
        userv1 := v1.Group("/users")
        {
            userv1.POST("", uc.Create)
            userv1.PUT(":name/change-password", uc.ChangePassword)
            userv1.Use(mw.Authn(), mw.Authz(authz))
            userv1.GET(":name", uc.Get)
            userv1.PUT(":name", uc.Update)
            userv1.GET("", uc.List)
            userv1.DELETE(":name", uc.Delete)
        }

        // 博客相关路由
        postv1 := v1.Group("/posts", mw.Authn())
        {
            postv1.POST("", pc.Create)
            postv1.GET(":postID", pc.Get)
            postv1.PUT(":postID", pc.Update)
            postv1.DELETE("", pc.DeleteCollection)
            postv1.GET("", pc.List)
            postv1.DELETE(":postID", pc.Delete)
        }
    }

    return nil
}
```

路由注册主要完成：
1. 注册默认的 404 处理器
2. 注册健康检查路由 `/healthz`
3. 注册性能分析工具 pprof 路由
4. 初始化授权模块和控制器
5. 注册登录路由
6. 创建 API 版本组 (`/v1`)，并在其下注册用户和博客相关路由

## 服务器启动

miniblog 启动了三种服务器：HTTP、HTTPS 和 gRPC，这里以 HTTP 服务器为例：

```go
func startInsecureServer(g *gin.Engine) *http.Server {
    // 创建 HTTP Server 实例
    httpsrv := &http.Server{Addr: viper.GetString("addr"), Handler: g}

    // 运行 HTTP 服务器
    log.Infow("Start to listening the incoming requests on http address", "addr", viper.GetString("addr"))
    go func() {
        if err := httpsrv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            log.Fatalw(err.Error())
        }
    }()

    return httpsrv
}
```

服务器启动流程：
1. 创建 `http.Server` 实例，设置监听地址和处理器
2. 在单独的 goroutine 中启动服务器
3. 错误处理并记录日志

## 优雅关闭

miniblog 实现了服务器的优雅关闭，确保在程序终止时能够处理完所有请求：

```go
quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit
log.Infow("Shutting down server ...")

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()

if err := httpsrv.Shutdown(ctx); err != nil {
    log.Errorw("Insecure Server forced to shutdown", "err", err)
    return err
}
```

优雅关闭的步骤：
1. 创建信号通道，并设置要监听的系统信号（`SIGINT` 和 `SIGTERM`）
2. 阻塞等待信号
3. 创建带超时的上下文
4. 调用服务器的 `Shutdown` 方法，给予 10 秒完成当前请求的处理
