# 模型层与数据库操作

## 什么是模型层

模型层（Model Layer）是[[MVC架构]]中的核心部分，负责：

1. 定义数据结构
2. 封装数据库操作
3. 实现业务逻辑

在Go Web开发中，模型层通常由以下几部分组成：
- 数据结构定义（struct）
- 数据库映射规则（ORM标签）
- 数据操作方法（CRUD）

## GORM框架基础

[[GORM]]是Go语言中最流行的ORM框架之一，它支持：

- 自动迁移：根据结构体定义自动创建表结构
- 关联关系：一对一、一对多、多对多
- 钩子方法：数据操作前后的自动处理
- 事务管理：自动或手动事务

### 基础用法示例

```go
// 定义模型
type User struct {
  ID       uint   `gorm:"primaryKey"`
  Name     string `gorm:"size:255;not null"`
  Email    string `gorm:"uniqueIndex"`
  Password string `gorm:"size:255;not null"`
}

// 自动迁移
db.AutoMigrate(&User{})

// 创建记录
db.Create(&User{Name: "张三", Email: "zhangsan@example.com"})

// 查询记录
var user User
db.First(&user, "email = ?", "zhangsan@example.com")

// 更新记录
db.Model(&user).Update("name", "李四")

// 删除记录
db.Delete(&user)
```

在Miniblog项目中，我们采用了以下模型设计：

```go
type UserM struct {
  ID        uint64    `gorm:"column:id;primary_key"`
  Username  string    `gorm:"column:username;not null"`
  Password  string    `gorm:"column:password;not null"`
  Nickname  string    `gorm:"column:nickname"`
  Email     string    `gorm:"column:email"`

  return "user"
}
```

## 数据库操作封装

在Web应用中，直接在业务逻辑层使用ORM操作数据库不是最佳实践。我们应该：

1. 创建仓储层（Repository）封装数据库操作
2. 提供统一的接口给业务层使用
3. 方便单元测试和模拟

### 仓储层接口设计

```go
// UserRepository 用户仓储接口
type UserRepository interface {
  Create(ctx context.Context, user *model.UserM) error
  Get(ctx context.Context, username string) (*model.UserM, error)
  Update(ctx context.Context, user *model.UserM) error
  Delete(ctx context.Context, username string) error
  List(ctx context.Context, offset, limit int) ([]*model.UserM, int64, error)
}

// PostRepository 文章仓储接口
type PostRepository interface {
  Create(ctx context.Context, post *model.PostM) error
  Get(ctx context.Context, postID string) (*model.PostM, error)
  Update(ctx context.Context, post *model.PostM) error
  Delete(ctx context.Context, postID string) error
  ListByUser(ctx context.Context, username string, offset, limit int) ([]*model.PostM, int64, error)
}
```

### MySQL实现

```go
// 用户仓储MySQL实现
type userRepo struct {
  db *gorm.DB
}

func (r *userRepo) Create(ctx context.Context, user *model.UserM) error {
  return r.db.WithContext(ctx).Create(user).Error
}

func (r *userRepo) Get(ctx context.Context, username string) (*model.UserM, error) {
  var user model.UserM
  if err := r.db.WithContext(ctx).Where("username = ?", username).First(&user).Error; err != nil {
    return nil, err
  }
  return &user, nil
}

// ... 其他方法实现
```

## 自动数据库迁移

GORM提供了自动迁移功能，可以在项目启动时自动创建或更新数据库表结构：

```go
// InitTables 初始化数据库表，自动迁移模型到数据库
func InitTables(db *gorm.DB) error {
  log.Infow("Starting database schema initialization...")
  
  models := []interface{}{
    &model.UserM{},
    &model.PostM{},
  }
  
  // 挨个迁移模型
  for _, model := range models {
    if err := db.AutoMigrate(model); err != nil {
      log.Errorw("Failed to migrate model", "model", model, "err", err)
      return err
    }
    log.Infow("Model migrated successfully", "model", model)
  }
  
  log.Infow("All database tables initialized successfully")
  return nil
}
```

## 事务管理

在涉及多表操作的场景中，事务管理非常重要：

```go
// 使用事务创建用户和默认文章
func CreateUserWithDefaultPost(db *gorm.DB, user *model.UserM, post *model.PostM) error {
  return db.Transaction(func(tx *gorm.DB) error {
    // 创建用户
    if err := tx.Create(user).Error; err != nil {
      return err
    }
    
    // 创建默认文章
    post.Username = user.Username
    if err := tx.Create(post).Error; err != nil {
      return err
    }
    
    return nil
  })
}
```

## 数据库索引优化

为提高查询性能，我们在数据表中添加了合适的索引：

1. 用户表：主键索引(id)、唯一索引(username)
2. 文章表：主键索引(id)、唯一索引(postID)、外键索引(username)

```sql
CREATE TABLE IF NOT EXISTS `user` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `username` varchar(255) NOT NULL,
  -- 其他字段省略
  PRIMARY KEY (`id`),
  UNIQUE KEY `idx_username` (`username`)
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS `post` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `username` varchar(255) NOT NULL,
  `postID` varchar(255) NOT NULL,
  -- 其他字段省略
  PRIMARY KEY (`id`),
  UNIQUE KEY `idx_postID` (`postID`),
  KEY `idx_username` (`username`),
  CONSTRAINT `fk_post_username` FOREIGN KEY (`username`) REFERENCES `user` (`username`)
) ENGINE=InnoDB;
```

## 最佳实践

1. **模型与表结构分离**：模型对象可能包含非数据库字段，使用标签控制映射关系
2. **统一错误处理**：对数据库错误进行统一处理，转换为应用错误码
3. **分页查询优化**：使用适当的索引和查询方法，避免全表扫描
4. **关注性能**：查询大量数据时使用游标或分批处理
5. **数据验证**：在入库前对数据进行格式和业务规则验证
